# 红笔 · 教师单机自用版 方案 V0.4

**版本**：V0.4（教师自用 · 云端 LLM · 带扩展性引导）
**定位**：部署在教师个人电脑上的内网工具。教师用手机拍照上传学生作业，系统调云端大模型自动批改并在原图打✅❌，教师在本机看板查看批改结果与学情分析。先只服务教师自己，家长端不做。界面从第一版起就为“学段—学科—班级”扩展留位。

---

## 一、版本定位与关键修正

### 1.1 定位

部署在教师个人电脑上的内网工具。教师手机拍照上传学生作业，系统调云端多模态大模型自动批改，原图打✅❌，教师在本机看板看批改结果与学情分析。核心价值：把教师从“逐题看对错、反复翻本子”的重复劳动中解放出来，时间用在看板分析和针对性教学上。

### 1.2 三项硬性架构决策

**① 批改算力在云端，不在教师电脑。** 教师电脑可能是性能较弱的个人笔记本或办公机，不假设有 GPU。教师自购大模型 API Key。电脑只需跑轻量后端、SQLite、看板和 API 调用，普通办公本即可。

**② 手机只连内网，电脑需能上外网。**

```
手机（内网 WiFi）→ 教师电脑（轻量后端 + SQLite + 看板）→ 云端多模态大模型 API → 返回结构化判定 → 电脑组装回显 → 落库 → 看板
```

手机不需要外网；电脑需要外网调 API。安装引导必须检查外网可达。

**③ IP 手动填 + 分系统图文引导 + 二维码兜底。** 不做自动发现、不做 mDNS。教师是成年人，查 IP 不是能力问题，是“不知道点哪里”的问题，给对引导即可。

### 1.3 界面扩展性原则（本版新增）

**从第一版起，学段、学科、班级都做成可选择、可扩展的结构，即使 MVP 只开放“小学 / 数学”。**

- 学段选择器：小学（开放）、中学（占位，显示“即将开放”）。
- 学科选择器：数学（开放）、语文（占位）、英语（占位）、作文（占位）。
- 班级选择器：教师可建多个班，每次进入默认上次选择的班。

占位项不是摆设：它们让数据模型、路由、看板结构从一开始就按“多学段多学科多班级”设计，后续开放新学科是“打开开关”，不是“重构系统”。

## 二、首次启动引导：三步选择，之后默认记住

### 2.1 首次进入流程

```
打开红笔（电脑浏览器 localhost:8080，或手机浏览器访问电脑IP）
  → 欢迎页
  → 第1步：选择学段
       [ 小学 ]  [ 中学（即将开放） ]
  → 第2步：选择学科
       [ 数学 ]  [ 语文（即将开放） ]  [ 英语（即将开放） ]  [ 作文（即将开放） ]
  → 第3步：选择/创建班级
       已有班级列表（点选）  +  [ + 新建班级 ]
       新建班级：填班级名称（如“三年级2班”）、学生名单（可粘贴导入，可留空后补）
  → 完成 → 进入工作台
```

### 2.2 默认记住机制

- 完成引导后，选择结果写入本地配置（`config.json` 或浏览器 localStorage）。
- **下次打开直接进入上次的“学段 + 学科 + 班级”工作台**，不再走引导。
- 工作台顶部常驻**当前上下文切换器**：

```
[ 小学 ▾ ] · [ 数学 ▾ ] · [ 三年级2班 ▾ ]
```

点任一项可切换；切换到未开放项时提示“该学段/学科即将开放”。切换班级即时生效，无需重启。

### 2.3 引导页的扩展预留（写进开发文档）

- 学段、学科用**配置表驱动**（`stage_config`、`subject_config`），不硬编码在页面里。新增学科 = 加一条配置 + 加一套批改 prompt 模板，不改前端结构。
- 班级数据模型从第一版就支持“一个教师多个班”，`class` 表带 `teacher_id`，`assignment` 表带 `class_id`。
- 引导流程做成可跳过、可重进（设置页有“重新配置”入口），避免教师选错后无法修正。

## 三、手机连接电脑：IP 配置引导

### 3.1 交互流程

```
手机浏览器首次访问 → 输入框：[ 192.168.1.100 ]（灰字提示格式）
  → 折叠面板“不知道怎么找？点这里看步骤”
       ├─ Windows 10 怎么查
       ├─ Windows 11 怎么查
       └─ Mac 怎么查
  → 点“连接” → 后端健康检查 → 成功则记住地址，下次直达
```

地址存手机浏览器 localStorage；看板设置页提供“修改电脑地址”。

### 3.2 分系统引导文案

**Windows 10**
1. 点左下角“开始”→“设置”（齿轮）。
2. 点“网络和 Internet”。
3. 左侧点“WLAN”（连 WiFi）或“以太网”（插网线）。
4. 点当前连接的网络名称，下方点“属性”。
5. 往下滚动找 **IPv4 地址**，形如 `192.168.x.x`。

**Windows 11**
1. 点“开始”→“设置”。
2. 左侧点“网络和 Internet”。
3. 点“WLAN”或“以太网”，再点当前连接的网络。
4. 页面中直接可见 **IPv4 地址**。
5. 备用：按 `Win + R`，输入 `cmd` 回车，输入 `ipconfig` 回车，看“IPv4 地址”。

**Mac**
1. 左上角苹果菜单 →“系统设置”。
2. 左侧点“网络”，点当前 Wi-Fi。
3. 点“详细信息…”→“TCP/IP”。
4. **IP 地址** 一栏形如 `192.168.x.x`。

**页面底部统一提示**：手机和电脑必须连同一个 WiFi；连不上时检查电脑防火墙是否允许本程序。

### 3.3 安装时一次性讲清网络前提

电脑端首次启动的安装页逐条检查：

1. 电脑已连 WiFi/网线，与手机同一网络。
2. 电脑能上外网（调云端 API 所需）——提供“测试外网”按钮。
3. 防火墙已允许本程序（首次运行弹窗点“允许访问”，或引导添加 8080 端口入站规则）。
4. 醒目展示访问地址 `http://IP:8080` 并生成**二维码**，手机扫码直达。

二维码是主路径，IP 输入框是扫不了码时的兜底，两者都保留。

## 四、云端大模型接入

### 4.1 模型适配层（可插拔，不锁死厂商）

```
LLMProvider 接口
  ├── QwenVLAdapter       （通义千问 qwen-vl）
  ├── GLM4VAdapter        （智谱 GLM-4V）
  ├── DoubaoVisionAdapter （豆包视觉）
  └── OpenAICompatAdapter （任意 OpenAI 兼容接口）
```

适配器负责请求构造、图片编码、JSON 输出约束、错误码映射、重试。业务层只依赖统一接口。MVP 先接 1 家主用 + 1 家备用。选型标准：中文手写识别能力、JSON 输出稳定性、价格、是否支持关闭“数据用于训练”。

### 4.2 API Key 管理

- 教师在设置页“模型配置”填入各厂商 key。
- key 加密存储本地（系统凭据管理器或本地密钥），不传手机端、不写日志。
- “测试连接”按钮调最小请求验证 key、外网、模型可用。
- 支持主用/备用 provider，主用失败自动切备用。

### 4.3 成本估算与控制

看板设置页内置成本估算器，输入教师所选模型的输入/输出单价，实时算出：

```
单份作业成本 ≈ 题目数 × (单题输入token + 输出token) × 单价
```

一份 15 题作业约 1–1.8 万 token；一个班 40 份约 40–70 万 token。界面展示“单份约 X 元、一个班约 Y 元”。不给死价，给算法，因厂商价格随时变。

成本控制开关：单次请求 token 上限；快路径（选择题、单一数值填空先规则精确匹配，命中不调 API）；缓存（同题图 + 同答案重复提交不重复计费）；批量模式（同页多题合并请求，MVP 默认一题一请求，稳定优先）。

### 4.4 云端调用失败处理

| 失败类型 | 处理 |
|---|---|
| 网络超时 | 自动重试 2 次（指数退避），仍失败标“待重试”，不丢数据 |
| 限流 429 | 排队降速，看板显示“云端繁忙，批改排队中” |
| key 失效/欠费 | 看板醒目提示，暂停队列 |
| 返回非 JSON | schema 校验失败 → 重试 1 次 → 仍失败标黄交教师复核 |
| 主 provider 故障 | 自动切备用 |

批改任务队列持久化，电脑重启后未完成任务可续。

### 4.5 数据合规提示

云端 API 意味着作业图片会发往模型厂商，必须透明：安装引导和设置页明确提示；建议选择支持关闭“数据用于训练”的厂商并确认关闭；支持“敏感信息遮盖”（P1，上传前对姓名栏打码）；学校有合规要求时由学校与厂商签约企业版。

## 五、手机端：连续扫描式上传

```
打开手机页面（已添加到主屏幕，地址已记住）
  → 顶部显示当前班级：[ 三年级2班 ▾ ]
  → 点“开始拍照”
  → 调起系统相机，取景提示四边对齐
  → 拍一张
  → 预览 + 5 秒倒计时 + [撤销重拍] / [立即上传]
       ├─ 5 秒内点“撤销” → 删除，回到拍照
       └─ 倒计时到 / 点“立即上传” → 上传到教师电脑
  → 自动回到拍照状态，连续拍下一张
  → 顶部队列：已上传 N / 批改中 M / 完成 K
```

**关键点**：

- 手机只负责“拍 + 传到电脑”，不直接调云端 API，key 不落手机，不依赖手机外网。
- 预览页做轻量质量预检（模糊/亮度），不合格标红提示重拍，可强行上传。
- 按“一次会话 = 一个学生”组织：拍前点选学生姓名，连续拍该生多页，点“完成这份”切下一个学生。
- 用 `<input type="file" accept="image/*" capture="environment">` 调系统相机，内网 HTTP 即可用，避开 HTTPS 门槛。

## 六、批改流水线

```
手机上传 → 电脑接收落盘 → 质量终检
→ 预处理（EXIF校正/透视纠偏/CLAHE）
→ 切题出坐标（CV版面分析，本地跑）
→ 组装请求（题目图 + 题干 + 标准答案 + 题型 + 知识点）
→ 调用云端多模态LLM（异步队列，JSON schema 强约束）
→ 规则交叉校验（数值等价/选项合法性/空答案/多次采样一致性）
→ 原图回显组装 → 落库 → 看板快照更新
```

本地负责：质量门禁、图像预处理、切题坐标、规则校验、回显渲染、落库、看板。云端负责：读题与判题。

切题坐标本地产出：回显对位依赖精确 `bbox_answer`，云端 LLM 的视觉 grounding 精度不足以直接支撑“像纸质批改”。

**LLM 输出强制 JSON schema**：

```json
{
  "judgement": "correct | wrong | partial",
  "student_answer_read": "1/2",
  "reason": "除号变乘时未取倒数，应为2",
  "error_type": "concept | calculation | reading | format",
  "confidence": 0.86
}
```

**规则交叉校验**：数值等价冲突、选项非法、空答案但有字迹、多次采样不一致——命中即标黄降置信度，进教师复核队列。

**标准答案**：教师拍照时或批改前录入（手输/拍答案页/复用答案模板）。同一练习册答案存一次，之后复用。这是云端批改的必要输入。

**教师复核**：低置信度题目标黄，看板点开修正（对/错/改错误类型），写入 `teacher_override`，与原始判定分开存。

**置信度融合**：`最终置信度 = f(LLM自报置信度, 规则校验冲突, 多次采样一致性, 该知识点历史准确率)`。低置信度题目在看板默认不计入统计或单独标注，避免把识别误差当学生知识漏洞。

## 七、教师看板

跑在电脑浏览器（`localhost:8080` 或局域网 IP），适配手机轻查看。顶部常驻学段/学科/班级切换器。三层结构：

**第一层 · 本次作业概览**：提交份数、已批完份数、班级平均正确率、最高/最低、与上次对比、批改队列状态。

**第二层 · 知识点掌握热力图**：知识点 × 正确率 / 错误人数 / 错误类型分布（计算/概念/审题/格式）。典型错例展示 `student_answer_read` 与正确答案对比。

**第三层 · 高频错题 + 教学建议**：按错误人数降序列题，附典型错误答案；LLM 基于结构化统计生成建议，prompt 锁定“只引用输入数据中的数字和错例”，不编造、不推断心理。

**设置页集中放置**：学段/学科/班级重新配置、模型配置（provider/key/测试连接）、成本估算器、IP 与二维码、备份恢复、数据合规提示。

## 八、数据模型（含扩展预留）

```
stage_config(id, name, enabled)            -- 小学/中学
subject_config(id, stage_id, name, enabled) -- 数学/语文/英语/作文
teacher(id, name)
class(id, name, teacher_id, stage_id, subject_id)
student(id, name, class_id)
assignment(id, class_id, title, subject_id, created_at)
submission(
  id, assignment_id, student_id, uploader_user_id,
  original_image_path, quality_flags JSON,
  quality_override BOOL, status
)
question_result(
  id, submission_id, question_no, question_type,
  knowledge_point_id,
  student_answer_text,
  correct_answer_text,
  llm_raw_output JSON,
  judgement_raw,
  judgement_final,
  error_type,
  confidence_final,
  rule_conflict_flags JSON,
  teacher_override,
  bbox_answer JSON,
  bbox_question JSON,
  created_at
)
knowledge_point(id, name, subject_id, parent_id)
app_config(key, value)   -- 记住的学段/学科/班级等本地配置
```

**关键约束**：

- `stage_config` / `subject_config` 驱动引导页和切换器，新增学科 = 加配置行，不改前端结构。
- `uploader_user_id` 与 `student_id` 必须并存，归属学生必填。
- `teacher_override` 独立于 `judgement_final`，保留原始判定。
- `llm_raw_output` 与 `rule_conflict_flags` 是审计、调 prompt、换模型评估的数据基础。
- 批改任务队列持久化表，重启可续。

## 九、数据存储与备份

- SQLite 单文件 + 本地图片文件夹，全部在教师电脑一个目录（如 `D:\RedPen\data`）。
- 图片按 `班级/作业/学生/页码` 组织。
- 一键备份：打包数据库 + 图片为 zip，教师拷 U 盘或网盘。电脑坏了数据就没了，必须有。
- 一键恢复：导入 zip 恢复。

| 里程碑 | 内容 | 验收标准 |
|---|---|---|

## 十一、一句话收束

V0.4 在 V0.3 基础上把“学段—学科—班级”做成从第一版就存在、可扩展、可记忆的上下文层：首次三步选择，之后默认直达，顶部随时切换，未开放项占位等待打开开关。批改算力在云端，教师电脑只需普通办公本 + 一个 API Key + 一个二维码；产品内核——质量门禁、切题坐标、规则校验、原图回显、看板归因、教师复核——一个不少。教师先自己用出减负效果，再谈家长端。
